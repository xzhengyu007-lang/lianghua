# 实时行情与交易架构

> 阶段 1 交付（行情层已实现并实测）；阶段 3 的交易层目前只有**设计**，代码尚未存在——本文把两者分开标注，
> 不把设计写成现状。日期 2026-11-09，基线提交 `45995fc` + 阶段 1 改动。

## 0. 一条铁律（有测试，不是注释）

**实时数据只服务「执行与监控」，绝不进入回测、因子、信号、训练路径。**

两个独立理由：实时价是**回测不可能知道的信息**（前视）；日线面板用的是**重建乘性总收益**口径，
而行情是原始价（腾讯"前复权"是加法复权，§23.19），混用会在除权日附近静默改变每个收益率。

守护在 `tests/test_realtime_isolation.py`，三道独立探针：

| # | 探针 | 抓什么 |
|---|---|---|
| 1 | 静态 import 图（AST，从 21 个研究模块 BFS） | 有人加了一行 `from .realtime import ...` |
| 2 | 干净解释器 subprocess 跑回测与 `latest_signal`，断言 `sys.modules` 里没有 `quant_system.realtime` | 传递依赖/property 里偷偷加载 |
| 3 | 把 transport 投毒成"一调用就抛断言"，重跑同一回测，要求净值**逐位相同** | "回测不需要行情"从断言变成测量 |

## 1. 数据流

```
腾讯 qt.gtimg.cn（GBK 文本，L1 快照，非官方免费源）

        ├──► SnapshotStore（sqlite：quotes + fetch_runs，带采集时间戳）

        └──► UI：顶栏新鲜度徽标 + 左栏状态灯（阶段 4）
```

## 3. 模块接口（`quant_system/realtime.py`）

| 名字 | 作用 |
|---|---|
| `parse_payload(text, *, fetched_at, calendar)` / `parse_sina_payload(...)` | 纯函数：GBK 文本 → `list[Quote]`。坏记录跳过（不补 0）；新浪的 0 价解析为"无报价" |
| `annotate(quote, *, now, stale_after=60, calendar)` | 唯一决定 `stale` 的地方；同时生成人话文案 |
| `session_state(ts, *, calendar)` / `fresh_floor(ts, *, calendar)` | 交易时段判定 / 当前"最新可接受行情时间"的下界 |
| **`TradingCalendar`** / **`load_calendar()`** | 交易日历：**从缓存里真实的 bar 日期推导**（见 §5.1），小时级缓存 |
| `limit_pct(symbol, name)` / `price_limit(...)` | 涨跌幅（复用 `data.infer_price_limit`，补 ST 5%）与涨跌停价（优先交易所值） |
| `sellable_shares(held, bought_today, frozen)` | T+1 可卖数量（纯算术，事实由账本提供） |
| `RateLimiter` / `with_backoff` / `chunks` | 3s 限频 / 指数退避 / 50 只分批 |
| `TencentQuoteSource` / **`SinaQuoteSource`** | 两个来源，同一 `fetch() -> (quotes, missing, errors)` 契约 |
| **`CrossCheckSource`** | 两源**并行**取价、价差 >0.5% 标 `suspect`；单源失败自动切换（见 §7.1） |
| `SnapshotStore` | sqlite（**WAL**）：`quotes`（每次采集一行）、`fetch_runs`（每轮一行）、`meta`；`latest/history/runs/last_run_at/prune` |
| `refresh(symbols, *, source, store, now, stale_after, calendar)` | 一轮：取价 → 标注 → 降级判定 → 落库 |
| `load_board(symbols, *, store)` | 离线板（`--offline`）：只读本地快照，全部按真实时间标注 |
| `throttle_remainder(store)` | 跨进程限频：两次 CLI 调用之间仍要满 3s |
| **`QuotePoller`** / **`PollerStatus`** | 桌面轮询器：3s 一轮，**首轮失败立刻黄灯**，连续失败 5 轮转红（见 §7.2） |
| `Board` | `tradable` / `fresh_ratio` / `stale_symbols` / `suspect_symbols` / `warnings` / `degraded` / `markdown()` / `to_dict()` |

CLI：`python -m quant_system quote --symbols=600519,300750 [--json] [--offline] [--no-cross-check] [--watch]`
（不给 `--symbols` 时读 `reports/signal_today/orders.csv`）。

## 4. 字段表（实测，不靠记忆）

2026-11-09 拉到的真实载荷：88 个字段（个股）／87 个（北交所）。0-based，按 `~` 切分：

| 下标 | 含义 | 下标 | 含义 |
|---:|---|---:|---|
| 0 | 市场标志（1=沪 51=深 62=北） | 30 | **行情时间** `yyyyMMddHHmmss` |
| 1 | 名称（GBK） | 31 / 32 | 涨跌额 / 涨跌幅 |
| 3 | 最新价 | 33 / 34 | 最高 / 最低 |
| 4 | 昨收 | 36 / 37 | 成交量（手）/ 成交额（万元） |
| 5 | 今开 | 43 / 44 / 45 / 46 | 振幅 / 流通市值 / 总市值 / 市净率 |
| 6 | 成交量（手） | **47 / 48** | **涨停价 / 跌停价** |
| 9 / 10 | 买一价 / 买一量 | 49 | 量比 |
| 19 / 20 | 卖一价 / 卖一量 | | |

三个实测陷阱（都写进了解析器）：

1. **`47/48` 并不总是有效**：指数返回 `-1`，北交所样本也返回 `-1` → 解析器把 ≤0 视为无效，按
   `昨收 × (1 ± 涨跌幅)` 计算并标 `source="computed"`。
2. **停牌的样子是"价格等于昨收、今开 0、成交量 0"**（`sz002129` 2026-11-06 实测）。把它当"平盘正常"
   会让交易台给停牌股排单，所以状态判定顺序里停牌优先于涨跌停。
3. **`[30]` 是交易所打印时间，不是我们采集的时间**：两者分开存，`stale` 只认前者。
   时间戳变成 `0` 时回退到采集时间并立刻判滞后——绝不静默重解释成"刚刚"。

## 5. stale 语义（禁止用旧价冒充现价）

两个独立判据，任一成立即为滞后：

1. 行情时间早于 `fresh_floor(now)`（跨了时段）；
2. 处于盘中，且 `now - 行情时间 > stale_after`（默认 60s，同一时段内但盘口没动）。

`fresh_floor` 随时段变化（周末与**节假日**都按"上一个交易日"处理，见 §5.1）：

| 时刻 | 下界 | 文案标签 |
|---|---|---|
| 09:30–15:00（盘中/午休） | 今日 09:30 | 今日盘中 |
| 09:15–09:30（集合竞价） | 今日 09:15 | 今日集合竞价 |
| 15:00 之后 | 今日 09:30 | 今日收盘 |
| 开盘前 / 非交易日 / 节假日 | 上一交易日 09:30 | 上一交易日收盘 |

### 5.1 交易日历：从缓存里的真实 bar 推导

"周一至周五"在节假日上恰好错在最要命的地方——国庆那天会等一个永不开始的开盘。本仓缓存里每个
`*_raw.parquet` / `*_tr.parquet` 的索引**就是交易所真实跑过的交易日**，所以日历直接用它：

- `TradingCalendar(days)`：`is_trading_day` / `previous_trading_day` / `covers`；
- `load_calendar()`：把 **536 个缓存文件**的索引做并集（`columns=[]` 只读索引），
  覆盖 **2004-01-14 .. 2026-11-06，5394 个交易日**，耗时约 **1.1–1.3s**，按小时缓存；
- 超出覆盖范围（例如 2030 年）回退到工作日规则，并把 `source="weekday"` 如实标出来。

实测：`2026-10-01`（国庆，周四）→ 非交易日、`session_state` 返回 `closed`、
`fresh_floor` 退到 **2026-09-30 09:30**；`previous_trading_day(2026-10-08)` → **2026-09-30**（跨过整段假期）。

> 踩过的坑写在这里：第一版按 mtime 采样 60 个文件，结果**最新的 mtime 全是退市股**（它们的历史停在
> 2026-07-13），日历因此止于 7 月，节假日又悄悄退回"工作日=开盘"。**"采样很快"不是理由，
> 覆盖率要靠断言守住**——`test_calendar_drops_a_real_public_holiday` 就是那个断言。

三种文案，绝不出现"旧价 + 现价"混排：

- 滞后：`延迟 N 分钟（最后更新 11-06 15:00:01，上一交易日收盘）`
- 收盘：`收盘价 11-06 15:00:01`
- 盘中：`现价 13:59:30`

**绝不做**：行情缺失时填 `0.00`；把采集时间当成行情时间；把 `stale` 的价格用于定量。

## 6. 交易状态与 T+1

状态机（`_classify`）：`no_quote`（价格 ≤0）→ `pre_open`（开盘前且无成交）→ **`suspended`（成交量 0 且今开 0）**
→ `limit_up` / `limit_down`（贴住涨跌停价 ±0.005）→ `normal`。

| 状态 | `can_buy` | `can_sell` | 说明 |
|---|:--:|:--:|---|
| normal | ✅ | ✅ | 唯一可以买入的状态 |
| limit_up | ❌ | ✅ | 涨停买不到，能卖出 |
| limit_down | ❌ | ❌ | 跌停卖不掉，也不该买 |
| suspended / pre_open / no_quote | ❌ | ❌ | 停牌不交易 |
| 任意 `stale=True` | ❌ | ❌ | 旧价不得定量 |

涨跌幅：主板 10%、创业板/科创板（300/301/688/689）20%、北交所（4/8 开头）30%，**ST 在主板上是 5%**
（创业板/科创板 ST 仍是 20%）。板块规则复用 `data.infer_price_limit`，与回测的可交易性判定同源。

T+1：`sellable_shares = max(0, 持仓 - 今日买入 - 冻结)`，纯算术，账本给事实。

## 7. 频控与重试

| 参数 | 值 | 理由 |
|---|---|---|
| 批量上限 | 50 只/请求 | 免费源实际容忍度 |
| 同源两轮间隔 | ≥3s（进程内 `RateLimiter` + 跨进程 `throttle_remainder`） | 单轮刷新 ≥3s 的要求；两次 CLI 调用也不得翻倍请求 |
| 重试 | 2 次尝试，等待 0.5s → 1s（上限 1s） | 吸收一次瞬时抖动，同时把"降级可见"压进 5s |
| 超时 | connect 1.5s / read 5s | 实测健康请求 0.30s，留 5 倍余量 |
| 降级预算 | 2×1.5s + 0.5s ≈ 3.5s（实测 4.5s，含 DNS/代理重试开销） | 见 §9 |

失败语义：单批失败→记入 `errors` 并继续其他批；整轮失败→回落到本地最后快照并**逐条标注滞后**；
`missing` 单独列出（有请求、无报价）。

### 7.1 双源交叉校验（腾讯 + 新浪）

单一免费源是这套方案唯一的结构性依赖，所以默认开双源：

| 情形 | 行为 | 用户看到 |
|---|---|---|
| 两源价差 ≤0.5% | 正常 | 正常，`sources=("tencent","sina")` |
| 两源价差 >0.5% | 标 `suspect=True`，`can_buy/can_sell=False` | 状态后面加 `⚠`，文案给两边的价 |
| 第二源挂了 | **warning**（不是 error），板子照常 | 摘要里"提示：第二来源不可用" |
| 第一源挂了 | **自动切换到第二源**，warning 写明"单一来源、未交叉校验" | 摘要里"腾讯不可用，本轮回落到新浪" |

两条实现要点（都是实测得来的）：

1. **只比价格**。新浪成交量单位是"股"、成交额是"元"，腾讯是"手"和"万元"——直接比会让每一只都"不一致"。
2. **0 不是价格**。停牌股新浪返回 `last=0`（腾讯返回昨收）。0 价一律按"无报价"跳过比较，表格里渲染成 `—`，
   绝不打印 `0.00`。
3. **两源并行**。串行时"两个源都挂"的代价是两份重试预算相加（约 7.5s，直接破 5s SLA）；
   并行后取较慢的那个（§9 实测 4.52s，与单源同价）。实现在 `CrossCheckSource.fetch` 里用 2 线程池。

### 7.2 轮询器：首轮失败就黄灯

同步的一轮可能花到 4.5s 才"证明"源挂了；桌面不能在这 4.5s 里继续显示绿灯。`QuotePoller` 的状态机：

| 状态 | 判定 | 文案 |
|---|---|---|
| 绿 | 上一轮没降级，且新鲜率 ≥90% | `行情正常（N/M 只可交易）` |
| 黄 | 本轮降级（第 1 次失败即黄）/ 新鲜率 <90% | `重连中（第 k 次失败）：原因` |
| 红 | 连续失败 ≥5 轮 | `数据源不可用（连续 5 轮失败）：原因；显示本地最后快照` |

- 黄灯时**仍然显示本地最后快照**（逐条标滞后），不是空白；
- 重试节奏比稳态更快（默认 1s vs 3s），恢复后立刻回绿；
- `tick()` 是纯状态推进，可单测；`start()/stop()` 只是一层 `threading.Thread`（daemon）。

## 8. 快照库 schema（sqlite，WAL）

```sql
quotes(symbol, name, price, prev_close, open_price, high, low, volume_lots, amount_wan,
       bid1, ask1, limit_pct, limit_up, limit_down, limit_source, status,
       quote_time, fetched_at, source,  PRIMARY KEY (symbol, quote_time, fetched_at))
fetch_runs(run_at PRIMARY KEY, requested, returned, errors)   -- 每轮都记，含失败轮
meta(key PRIMARY KEY, value)                                   -- last_prune
```

默认路径 `reports/realtime/quotes.sqlite`（`reports/` 在 `.gitignore` 内）。

两条运维事实：

- **WAL + 每次调用即关连接**：3s 轮询下写者与读者（UI）会互相阻塞；`journal_mode=WAL` 写进文件头，
  `_session()` 负责 commit 并**关闭**连接（不复用、不泄漏文件句柄）。
- **保留策略**：3s 一轮对 50 只票 = 每小时约 6 万行，**必须**有界。`prune()` 对超过 `keep_days`（默认 60 天）
  的日子只留**当天首末两行**（开盘/收盘仍在），中间行删除；`fetch_runs` 按同样边界清理。
  自动裁剪**每天最多一次**（`meta.last_prune` 闸门），不会在盘中每 3s 跑一次 DELETE。

## 9. SLA 实测（本机，2026-11-09 02:35 / 03:05，真实接口）

| 指标 | 目标 | 实测 | 条件 |
|---|---:|---:|---|
| 行情刷新（4 只，单源） | ≤3s | **0.30s** | 进程已预热 |
| 行情刷新（4 只，**双源交叉校验**） | ≤3s | **0.31s** | 两源并行，不比单源慢 |
| 行情刷新（50 只，单请求上限，双源） | ≤3s | **0.36s** | 50 只取自缓存清单，含退市股，31 只按定义滞后 |
| 首次调用额外开销 | — | **+0.7～1.3s** | 构建交易日历（536 个索引），之后按小时缓存 |
| 断线 → 降级可见（单源） | ≤5s | **4.52s** | 代理指向关闭端口（黑洞最坏情况） |
| 断线 → 降级可见（**双源都挂**） | ≤5s | **4.52s** | 并行取价，不叠加两份预算 |
| 断线重连（网络恢复后第一轮） | ≤5s | **0.31s** | — |
| 轮询器黄灯延迟 | <1s | **一轮耗时（0.31s 健康 / 失败当轮即黄）** | `QuotePoller.tick()`，不等重试预算耗尽 |
| 两轮间隔（同一 source） | ≥3s | **2.99s** | 限频生效（跨进程由 `throttle_remainder` 保证） |
| 首屏可交互 | ≤1s | 未测 | 阶段 4（UI 尚不存在） |
| 建议生成 | ≤10s | 未测 | 阶段 2（现有 `signal` 命令约 5s，待正式计时） |
| 下单前校验 | ≤500ms | 未测 | 阶段 3（校验器尚不存在） |

## 12. 已知限制

1. **交易日历来自缓存，不是交易所公告**：覆盖 2004-01-14 至归集时最新一天（实测 5394 个交易日）；缓存之外的
   日期回退到工作日规则，并用 `source="weekday"` 如实标出。临时停市（台风、突发）不会出现在缓存里，当天会被
   当成交易日——此时盘口给的是"上一交易日收盘"，仍按滞后标注，不会冒充现价。
2. **非官方免费源**：可能限流、改字段或下线。双源交叉校验能发现"两边不一致"，但两个源同时改协议时仍要改解析器。
   交叉校验的代价是请求量翻倍（两源各自 3s 一轮），`--no-cross-check` 可关掉。
3. **无 L2**：不给盘中择时用，这是刻意的。
4. **不解决除权**：行情是原始价，只用于展示与执行；历史序列仍走重建总收益缓存，两者不混用（§0）。
5. **阶段 2/3/4 的指标（建议生成、下单校验、首屏）尚无实测值**，表中标"未测"，不写估算值冒充实测。
6. **`suspect` 只说明"两个免费源不一致"**，不说明谁对：要么人工看一眼，要么换第三个来源确认。它只会把
   `can_buy/can_sell` 变成 False，不会自动选边。
