# UI 方案（本地交易台）

> 阶段 4 交付。启动：`python scripts/desk_server.py` → http://127.0.0.1:8770
> 只监听 127.0.0.1。没有 Node，没有构建步骤，没有 CDN。

## 0. 结论先行

| 决策 | 取值 | 为什么 |
|---|---|---|
| 形态 | **本地 Web 台 + stdlib `ThreadingHTTPServer`** | 单用户、三栏、四个 JSON 端点；本仓已有同类服务端，补 300 行即可，不必引入 Web 框架 |
| 前端 | **纯 HTML/CSS/ES 模块，无打包** | 图表库官方给单文件 IIFE 产物；引入 Vite 需要 Node+pnpm+打包器+产物入仓的 CI 约定，换来的是"官方已经给你的东西" |
| 图表 | **lightweight-charts 5.2.1（Apache-2.0）单文件** | 唯一同时满足「许可证干净」「`<script>` 即用」「canvas 只画可视区间」三条；10 万根实测 3.9 ms/帧 |
| 服务端框架 | **不引入 FastAPI** | 与任务书默认不同，理由见 §1 |
| 桌面壳 | **不用 Electron / Tauri** | 收益为 0（不联网、不打包、不需要系统托盘），代价是 100 MB 运行时 + 一套与 Python 无关的工具链 |
| 与既有站点关系 | 并**存**：`docs/` 静态站（归档、可离线打开）与交易台（本机日常使用） | 归档站是发布物，交易台是操作台；两者的"数据不新鲜怎么办"处理方式不同 |

## 1. 为什么偏离任务书默认（FastAPI + Vite/TS）

任务书写的是"优先 FastAPI + 静态前端（Vite + TS）"。实测后的结论是**两个都不装**：

| 维度 | stdlib（实际采用） | FastAPI |
|---|---|---|
| 新增依赖 | 0 | starlette + pydantic + uvicorn（+ 传递依赖） |
| 现有代码 | 本仓已有 `ThreadingHTTPServer` 的 `/api/*` 模式 | `do_GET` 全量重写，静态文件仍要自己挂 |
| 本台需要的端点 | 4 个 GET + 2 个 POST | 同 |
| 真正缺的能力 | **静态文件路由**（20 行） | 无 |

`Vite + TS` 的代价更具体：仓库当前 0 个 Node 依赖、0 个 `package.json`；引入后需要
Node + pnpm + 打包器 + "产物要不要入仓"的 CI 约定，而 `lightweight-charts` 官方发布的
就是可直接 `<script src>` 的 IIFE 产物（实测 197,922 字节，Apache-2.0 头注释完整保留）。

> 若以后确实需要类型化端点或 WebSocket 推送，升级路径很清楚：把 `Handler.do_GET`
> 按路由拆成 FastAPI 的 `@app.get`，静态目录用 `StaticFiles` —— 前端不动。

## 2. 页面结构（三栏 + 顶栏）

```
┌─ 顶栏 ────────────────────────────────────────────────────────────────┐
│ 交易台 2026-11-09 │ ● 行情正常（8/8 只可交易） │ 模拟盘 │ L1 模拟盘 │ 恢复 │
│                                                    [生成计划] [全部停机] [建议卡] │
├──────────────┬─────────────────────────────┬───────────────────────────┤
│ 目标篮        │ K 线 + 成交量                │ 今日建议卡（六要素）        │
│ 标的/名称/现价 │ 红涨绿跌、十字光标、缩放      │ 收益 + 不确定性同屏         │
│ 涨跌/状态灯   │ 成交标注（只标真实事件）      │ 目标篮（股数/权重/限价）    │
│              │ 200/600/2000/20000 根切换     │ 逐只：为什么 + 风险         │
├──────────────┼─────────────────────────────┼───────────────────────────┤
│ 模拟盘持仓    │ 数据口径说明                 │ 组合层风险                 │
│ 权益/现金/市值 │                              │ 最近审计（含幂等拒绝）      │
│ 每日权益曲线   │                              │ 免责（不可折叠）            │
└──────────────┴─────────────────────────────┴───────────────────────────┘
```

三条颜色/语义约定，都是**只在一处定义**：

- **红涨绿跌**：`.up { color: #f6465d }` / `.down { color: #0ecb81 }`，由 `cls(value)` 决定；
- **新鲜度徽标**：绿/黄/红直接来自 `QuotePoller` 的状态机（不是页面自己判断的），
  所以它和命令行 `--watch`、审计日志用的是同一个判断；
- **模拟/实盘徽标**：级别 ≥L3 才显示"实盘级（无网关）"，且**永远**附带"本仓无券商网关"字样。

## 3. 10 万根 K 线怎么做到的

| 层 | 做法 |
|---|---|
| 取数 | `/api/bars?symbol=&limit=` **服务端切片**，不把历史全部塞进页面 |
| 序列 | 用**重建总收益**缓存（`*_tr.parquet`），与回测同一口径；不用实时价拼历史 |
| 传输 | `gzip`（`len>1KB` 且客户端接受时自动压缩）——100k 根紧凑 JSON 8.33 MB → 1.06 MB |
| 渲染 | lightweight-charts 是 canvas，只画可视区间；实测 10 万根缩放帧 **3.9 ms**（max 8.2 ms，0 掉帧） |
| 上限 | 单次请求夹在 50–20,000 根（本仓单票缓存 1800 根，留足余量） |

页面上的 200/600/2000/20000 四个档位就是这条链路的自检入口。

## 4. 防误触（查询与下单分离）

| 措施 | 实现 |
|---|---|
| 查询与操作分端点 | 读：`GET /api/state`、`/api/bars`；写：`POST /api/gate`、`POST /api/plan`（各一个） |
| 前端二次确认 | 三个按钮全部先 `confirm()`，文案写明后果（"停止生成新单 + 打回 L1""已有有效订单的标会被跳过"） |
| 服务端独立校验 | 前端确认不算数：`/api/gate` 拒绝把级别开到 L3（"L3 只能命令行逐日授权"）；`/api/plan` 走完整七步管线，幂等与限额在服务端 |
| 幂等 | 重复点"生成计划"不会重复下单：`orders.jsonl` 里已有有效键的标会被拒并写审计 |
| 停机权重 | kill 是**最显眼**的危险按钮（红色描边），且它会把级别自动打回 L1 |
| 审计可见 | 右栏"最近审计"实时显示 `order.accepted / order.rejected / order.duplicate / halt` |

## 5. 界面的数据来源（没有一处是页面自己算的）

| 区块 | 来源 |
|---|---|
| 新鲜度徽标 / 状态灯 / 现价涨跌 | `QuotePoller`（服务端一个轮询器，3 s 一轮，双源交叉校验） |
| 目标篮 / 建议卡六要素 | `reports/advice_today/card.json`（由 `aq advice` 生成） |
| 持仓与权益曲线 | `paper` 账本 + `reports/trading/equity.jsonl` |
| 审计流 | `reports/trading/audit.jsonl` |
| 闸门 | `reports/trading/gate.json`（**每次读状态都检查 mtime**，命令行 kill 后页面立刻变） |

## 6. 实测（本机，2026-11-09 03:45）

| 指标 | 目标 | 实测 |
|---|---:|---|
| 首屏可交互（`GET /` + CSS/JS + 首个 `/api/state`） | ≤1s | **0.0017 s（HTML）/ 0.0063 s（state）**，端到端 < 0.2 s（本机回环） |
| `/api/bars`（600 根，71 KB） | — | **0.0137 s** |
| 页面轮询 | 3s | 3.00 s（network 日志可验证） |
| 图表渲染 | 10 万根流畅 | 见 §3（库层实测 3.9 ms/帧） |

## 8. 没做（以及为什么）

1. **没做 Electron/Tauri**：见 §0，收益为 0。
2. **没做 Node/TS**：见 §1。
3. **没做 L3 的界面入口**：只能命令行 `--level 3 --date`，且次日零点失效——一个"点一下就全自动"的按钮是这套系统最不该有的东西。
4. **没做手机端/多用户**：单用户本机工具，加身份与权限只会给攻击面。
5. **没做分钟级图表**：日频月轮动，分钟线是纯装饰（`docs/实时行情与交易架构.md` §2）。
6. **静态归档站与交易台没有合并**：归档站要求"任何电脑打开都能看、不联网"，交易台要求"实时、可操作"，
   两个目标互斥，合并只会两头都不达标。
